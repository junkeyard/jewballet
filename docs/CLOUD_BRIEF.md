# 쥬발레아카데미 QR 체크인 — 클라우드 개발 브리프

모든 클라우드 세션은 이 문서를 먼저 읽고, 여기 적힌 완료 조건으로 스스로를 판정한다.
관련 문서: `docs/v2-design.md`(v2 설계안) · `design.md`(디자인 시스템·확정 문구) · `supabase/*.sql`(스키마)

## 1. 제품 정의

- **성인 위주 발레 학원 1곳**의 회원·수강권·출석·매출 관리 웹앱.
- **출석 방식은 바꾸지 않는다**: 학원 입구에 붙은 QR 인쇄물 → 회원이 **자기 폰 카메라**로 스캔 →
  브라우저에서 `/check-in` 열림 → 전화번호 뒤 4자리로 출석. **별도 앱 설치를 요구하지 않는다.**
- 사용자: ① 회원(성인, 모바일 브라우저) ② 원장·강사(관리자, PC와 폰 둘 다).
  **학부모 기능은 만들지 않는다**(성인 위주라 대상이 아님).
- 앱스토어 출시는 **나중의 확장 계획**이다. 지금은 웹으로 끝내되 PWA(manifest·아이콘·홈 화면 추가)까지만
  준비해 나중에 감싸기 쉽게 둔다. 네이티브 앱·Capacitor·Expo 작업은 하지 않는다.

## 2. 비교 기준

**StudioMate(스튜디오메이트)** 수준 — 필라테스·요가·발레 스튜디오용 회원·수강권·출석·매출 관리 서비스.
세션이 웹에서 공개 자료(소개 페이지·기능 목록·스크린샷)를 조사해 **기능 격차표**를 `docs/benchmark.md`에 남기고,
이 학원 규모(강사 소수·회원 수십~백여 명)에 의미 있는 격차부터 메운다. 예약·강사 급여·다지점 같은
대형 기능은 격차표에 "보류(규모 불일치)"로 적고 만들지 않는다.

## 3. +@ 중점: 매출 증대·리텐션

성인 회원은 **스스로 결제하고 스스로 그만둔다.** 재등록을 놓치지 않는 것이 매출의 핵심이다. 후보(우선순위순):

1. **재등록 관리** — 만료 D-14/D-7/D-0·잔여 2회 이하 회원 목록, 재등록 여부 추적, 재등록률(월별).
2. **이탈 위험 감지** — 평소 출석 주기 대비 공백이 긴 회원(예: 최근 14일 무출석, 평소 대비 빈도 급감).
3. **휴면 회원 복귀** — 만료 후 미재등록 회원 목록과 복귀 제안 문구.
4. **매출 대시보드** — 월 매출, 신규/재등록 매출 구분, 객단가, 수강권 유형별 판매, 회원 LTV.
5. **수강권 운영** — 일시정지(홀딩)·연장, 체험권→정규 전환 추적, 추천인 기록.
6. **동기부여(성인)** — 누적 출석·연속 출석 마일스톤을 체크인 성공 화면에 표시(유치하지 않게).

**메시지 발송은 자동화하지 않는다.** 카카오 알림톡 등은 계약·비용이 필요하므로, 대상자 목록과
**복사해 붙여 넣을 문구**(개인화 치환 포함)를 만들고, 발송 어댑터는 인터페이스와 스텁만 둔다.

## 4. 바꾸지 않는 것 / 제약

- **기존 DB 스키마와 데이터는 바꾸거나 지우지 않는다.** 새 기능은 `supabase/006_*.sql`부터
  **추가형 마이그레이션**(새 테이블·컬럼·뷰·함수)으로만. `002`처럼 데이터를 지우는 SQL은 쓰지 않는다.
- 실제 DB 적용 상태: 001만 적용 확인, 003·004·005는 미적용(2026-07-22 실측). 새 마이그레이션은
  **003→004→005 적용을 전제**로 쓰고, 파일 머리에 의존 순서를 적는다.
- **실제 Supabase·실제 키에 접속하지 않는다.** 저장소에 `.env.local`은 없다. 테스트는 로컬 Postgres
  (가능하면)나 데이터 계층 목(mock)으로 돌린다. 비밀값·실명·전화번호를 커밋하지 않는다(테스트 데이터는 가짜).
- 스택: Next.js App Router + `@supabase/supabase-js`(서버 전용 service role). 의존성 추가는 이유를 PR에 적는다.
  `npm audit fix --force` 금지(Next를 낮춘다).
- 문구·색·간격은 `design.md`를 따른다. 오류 문구는 6.5 매핑(행동 안내형).
- **현재 요금제(plans) 데이터는 예시일 뿐 실운영 값이 아니다**(2026-09-28 사용자). 요금 체계 개편은 틀이 잡힌 뒤
  별도 단계에서 한다. 그러니 지금은 요금제 이름·가격·횟수를 **코드에 박아 넣지 말고** 전부 데이터와 관리자 화면
  (상품 탭)에서 바꿀 수 있게 만든다. StudioMate 기준으로 필요한 요금제 속성(예: 기간제/횟수제, 주당 횟수 한도,
  홀딩 가능 일수, 체험권 여부)은 추가형 컬럼·테이블로 넣어 두면 개편 때 값만 채우면 된다.

## 5. 완료 조건 (모든 PR 공통)

- `npm run build`·`tsc --noEmit`·lint 통과, `npm audit` 고위험 0건.
- **Playwright E2E**를 모바일 WebKit(iPhone 계열)·모바일 Chromium(Android 계열)과 데스크톱 Chromium에서 실행해 통과.
  폭 360·390·430px에서 **가로 스크롤·잘림·겹침 없음**을 스크린샷으로 남긴다(`docs/screens/`).
- **반복 안정성**: 체크인 흐름을 같은 회원으로 **연속 20회** 돌려 오류 0건.
  같은 회원이 짧은 시간(예: 10분) 안에 다시 스캔하면 **횟수를 두 번 차감하지 않는다**(멱등 보장, 테스트 포함).
- 네트워크 실패·만료·잔여 0·미등록 번호·동명(뒤 4자리 중복) 같은 **실패 경로도 테스트**한다.
- 접근성: 입력 56px+·버튼 52px+, 대비 WCAG AA, 스크린리더 레이블.
- Lighthouse 모바일(성능·접근성·권장사항) 90 이상을 목표로 측정값을 PR에 적는다.
- PR 본문에 **실제로 검증한 것 / 검증 못 한 것**을 나눠 적는다. 가상 테스트 통과를 실사용 검증으로 적지 않는다.

## 6. 사람이 하는 것 (세션 범위 밖)

QR 인쇄물 교체 · 메시지 실제 발송.
