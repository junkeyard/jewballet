# 클라우드 세션 요청문

같은 저장소를 여러 세션이 동시에 고치면 충돌하므로, **S1을 먼저 끝내 병합한 뒤** S2·S3·S4를 병렬로 돌리고,
마지막에 S5로 전체를 점검한다. 각 세션은 `main`에서 브랜치를 따서 PR 하나로 끝낸다.

## S1 — 기반 (먼저, 단독)

```
docs/CLOUD_BRIEF.md를 기준으로 작업해줘. 이번 범위는 "기반"이야.
1) Playwright E2E 환경: 모바일 WebKit·모바일 Chromium·데스크톱 Chromium, 폭 360/390/430 스크린샷 저장.
2) 실제 Supabase 없이 도는 테스트 데이터 계층(로컬 Postgres가 되면 그것, 아니면 목)과 가짜 시드.
3) 003→004→005 적용 상태를 전제로 한 스키마 문서화(docs/schema.md)와, 체크인 멱등성(짧은 시간 재스캔 이중 차감 방지)에
   필요한 추가형 마이그레이션 006.
4) StudioMate 공개 자료 조사 → docs/benchmark.md 기능 격차표(이 학원 규모에서 만들 것/보류).
5) PWA 기본(manifest·아이콘·홈 화면 추가).
기존 화면 동작은 바꾸지 말고, 현재 동작을 E2E로 고정하는 테스트부터 써줘.
```

## S2 — 회원 화면 (S1 병합 뒤, 병렬)

```
docs/CLOUD_BRIEF.md와 docs/benchmark.md를 기준으로 회원 쪽(/, /check-in, /member)을 StudioMate 수준으로 다듬어줘.
QR 스캔 직후 첫 화면부터 출석 완료까지 탭 수를 최소로, 성공 화면에 잔여 횟수·만료일·누적/연속 출석 마일스톤.
실패 경로(만료·잔여 0·미등록·뒤 4자리 중복·네트워크 오류)마다 행동 안내 문구와 테스트.
완료 조건 5절 전부(특히 20회 반복·폭 3종 스크린샷)를 PR에 증거로 첨부.
```

## S3 — 관리자·매출 (S1 병합 뒤, 병렬)

```
docs/CLOUD_BRIEF.md 기준으로 /admin을 다듬고 매출 대시보드를 추가해줘(브리프 3절 4번).
월 매출·신규/재등록 구분·객단가·수강권 유형별 판매·회원 LTV. 필요한 집계는 추가형 뷰/함수(006 이후 번호)로.
관리자는 PC와 폰 둘 다 쓰므로 폰 폭에서도 표가 깨지지 않게. 완료 조건 5절 준수.
```

## S4 — 리텐션 (S1 병합 뒤, 병렬)

```
docs/CLOUD_BRIEF.md 3절 1·2·3·5번을 구현해줘: 재등록 관리(만료 임박·잔여 적음·재등록률),
이탈 위험 감지(평소 주기 대비 공백), 휴면 복귀 목록, 홀딩·연장·체험→정규 전환·추천인 기록.
메시지는 자동 발송하지 말고 대상 목록 + 개인화된 복사용 문구 + 발송 어댑터 스텁까지.
S3와 파일이 겹치면 관리자 탭을 새로 추가하는 쪽으로 충돌을 피해줘. 완료 조건 5절 준수.
```

## S5 — 통합 점검 (마지막, 단독)

```
main 기준으로 docs/CLOUD_BRIEF.md 완료 조건 5절을 처음부터 끝까지 다시 검증해줘.
전 화면 폭 3종 × 브라우저 3종 스크린샷, 체크인 20회 반복, Lighthouse 측정, 문구가 design.md와 맞는지,
테스트가 없는 실패 경로가 있는지. 고칠 것은 고치고, 사람이 실기기에서 확인할 체크리스트를 docs/manual-qa.md로 남겨줘.
운영 매뉴얼 개정 초안(docs/operations.md)도: DB 적용 순서, Vercel 환경변수, QR 인쇄물 교체.
```
